# ReplyMate AI privacy notice (self-hosted build)

This example app has no ads, analytics SDK, tracking SDK or independent backend. It listens to Android notifications only after the user explicitly grants notification access. This OS-level permission is powerful and may allow access to notifications from applications other than WhatsApp, even though this source code checks the notification package ID before reading its message text.

On a matching WhatsApp message, the app uses the display name and newest notification text to request a reply from Google's Gemini API. It also sends the owner's configurable personality instructions, optional non-sensitive facts provided by the owner, and up to four recent user/reply pairs for that contact (only replies actually sent through ReplyMate). Google handles the request under its own API privacy terms; free-tier inputs may be used for product improvement. The app does not upload a full WhatsApp chat history or contact book. Do not enable the app for confidential conversations.

On-device storage contains: notification settings, exact-match allow/block display names, personality instructions, the optional owner-provided details, local daily counters and an API key encrypted with the Android Keystore. Owner-provided details are saved in Android DataStore and are not encrypted by the app; do not enter sensitive facts. Incoming messages, generated review drafts, and recent per-contact conversation pairs remain in process memory only, not a persistent database. Recent chat pairs are restricted to four successful replies and expire after two hours. Manual drafts can disappear if Android terminates the process. On app removal, the key and settings are removed (Android backup is disabled).

The developer cannot guarantee delivery or WhatsApp account safety; experimental automation may violate platform policies. The user must explicitly turn on the master switch, then separately confirm any automatic-reply mode. Default settings are OFF, manual review, and approved-contacts-only.

The duplicate guard additionally saves a random salt, salted SHA-256 fingerprints and receipt times in private on-device preferences for up to 15 minutes (bounded to 1,024 records). Outgoing fingerprints are used for 10 minutes within that storage window. It stores neither message text nor contact names. These hashes can still reveal equality and timing; this is not a chat history database. Background settings store whether you requested a foreground session, explicitly stopped it, and opted into reboot recovery. Reboot recovery is disabled by default. No extra message contents or keys are sent to GitHub Actions or diagnostics.
